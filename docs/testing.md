## Команды

Запуск всех тестов:

```bash
poetry run pytest
```

Запуск без pytest cache plugin, если нужно исключить локальный cache state:

```bash
poetry run python -m pytest -q -p no:cacheprovider
```

Поиск тестов:

```bash
poetry run pytest --collect-only -q
```

Django system check:

```bash
poetry run python manage.py check
```

Линтер:

```bash
poetry run ruff check .
```

Проверка миграций выполняется в Docker Compose после пересборки контейнера:

```bash
docker compose up -d --build
docker compose exec web python manage.py makemigrations --check --dry-run
docker compose exec web python manage.py migrate
```

## Уровни тестирования

1. Тесты моделей — текущий завершённый уровень для базовых моделей.
2. Тесты сервисов — следующий уровень после появления `cart/services.py`, `orders/services.py`, `reviews/services.py`.
3. Тесты views — после реализации web-страниц.
4. Тесты API — после реализации DRF endpoints.

Приоритет — модели и сервисы, потому что именно там должны находиться бизнес-правила.

## Модели

### users

Покрыто:

- пользователь создаётся с `username`, `email` и паролем;
- `USERNAME_FIELD` равен `username` согласно ADR 0007;
- `email` необязателен;
- если `email` указан, дублирующийся email отклоняется;
- `str(user)` возвращает `username`.

### catalog.Category

Покрыто:

- категория создаётся с `name` и `slug`;
- `slug` уникален;
- `str(category)` возвращает название;
- новая категория активна и не удалена;
- поддерживается вложенность через `parent`;
- `soft_delete()` и `restore()` меняют `is_deleted` и `deleted_at`.

### catalog.Product

Покрыто:

- товар создаётся с ключевыми полями каталога;
- `slug` уникален;
- `sku` уникален;
- цена не может быть отрицательной;
- старая цена не может быть отрицательной;
- остаток не может быть отрицательным;
- `is_available` истинно только для активного, не удалённого товара с положительным остатком;
- `soft_delete()` делает товар недоступным;
- `restore()` снимает soft-delete флаг.

### catalog.ProductImage

Покрыто:

- изображение связано с товаром;
- сохраняются `image`, `alt_text`, `is_main`, `sort_order`;
- строковое представление содержит название товара.

### cart.Cart

Покрыто:

- DB-корзина принадлежит пользователю;
- у пользователя может быть только одна постоянная DB-корзина;
- `total_items` считает количество всех позиций;
- `total_price` считает сумму всех позиций.

### cart.CartItem

Покрыто:

- стоимость позиции считается как цена товара на количество;
- один товар не может быть добавлен в одну корзину двумя строками;
- количество позиции должно быть строго положительным.

### orders.Order

Покрыто:

- заказ принадлежит пользователю;
- начальный статус соответствует `Order.Status.NEW`;
- итоговая сумма не может быть отрицательной;
- `recalculate_total_price()` учитывает все позиции заказа.

### orders.OrderItem

Покрыто:

- позиция связана с заказом и товаром;
- цена сохраняется как snapshot;
- название товара сохраняется как snapshot;
- изменение товара после заказа не меняет snapshot;
- цена позиции не может быть отрицательной;
- количество должно быть строго положительным.

### payments.Payment

Покрыто:

- платёж связан с заказом;
- у одного заказа может быть несколько платежей согласно ADR 0008;
- сумма платежа не может быть отрицательной;
- `is_successful` истинно только для `succeeded`;
- `is_final` корректно работает для финальных и ожидающих статусов.

Ограничение `не больше одного успешного платежа на заказ` относится к будущей сервисной логике оплаты и будет проверяться в service tests.

### reviews.Review

Покрыто:

- отзыв связывает пользователя и товар;
- пара `user + product` уникальна;
- один пользователь может оставить отзывы на разные товары;
- разные пользователи могут оставить отзывы на один товар;
- рейтинг ограничен диапазоном `1..5`;
- `is_published` истинно только для опубликованного статуса.

## Сервисы

### cart

Будет покрыто после реализации сервисного слоя:

- добавление товара в корзину;
- изменение количества;
- удаление товара;
- запрет количества больше остатка;
- корректный расчёт итоговой суммы;
- merge session-cart в DB-cart после входа пользователя.

### orders

Будет покрыто после реализации checkout service:

- создание заказа из корзины;
- создание позиций заказа;
- уменьшение остатков;
- очистка корзины;
- запрет заказа сверх остатка;
- snapshot цены и названия товара;
- атомарность создания заказа.

### reviews

Будет покрыто после реализации review service:

- нельзя оставить отзыв без покупки, если правило включено;
- нельзя оставить второй отзыв на тот же товар;
- рейтинг ограничен диапазоном `1..5`;
- модерация меняет статус отзыва контролируемо.

## API

Будет покрыто после реализации DRF endpoints:

- `GET /api/products/` доступен всем;
- создание заказа требует JWT;
- пользователь видит только свои заказы;
- чужой заказ недоступен;
- создание отзыва требует JWT.

## Минимальный Definition of Done для фичи

Фича считается готовой, если есть:

- код;
- миграции, если изменилась модель;
- тесты ключевых бизнес-правил;
- обновлённая документация, если изменилось поведение;
- зелёные `check`, `ruff`, `pytest`.
