# ADR 0012: Правило похожих товаров на странице товара

## Статус

Принято.

## Контекст

На этапе 7 реализуется детальная страница товара.

Roadmap этапа 7 предполагает отображение блока похожих товаров. При этом в текущей модели каталога ещё нет расширенных признаков для построения рекомендаций:

- тегов;
- брендов;
- атрибутов;
- истории просмотров;
- пользовательской аналитики;
- полноценной рекомендательной системы.

На текущем этапе у товара уже есть базовые признаки:

- категория;
- цена;
- остаток;
- активность;
- soft delete;
- связь с заказами через `OrderItem`.

Конфликт `C010` связан с выбором минимального правила похожих товаров, достаточного для этапа 7.

## Рассмотренные варианты

### Вариант A: похожие товары из той же категории

Плюсы:

- реализуется на текущей модели;
- не требует новых таблиц;
- не смешивает этап 7 с аналитикой или заказами;
- поведение легко покрыть тестами.

Минусы:

- рекомендации грубые.

### Вариант B: похожие товары по категории и близкой цене

Плюсы:

- рекомендации немного точнее.

Минусы:

- логика сложнее;
- нужны дополнительные правила и тесты;
- польза для текущего MVP сомнительна.

### Вариант C: популярные или часто покупаемые вместе

Плюсы:

- ближе к реальному e-commerce.

Минусы:

- заказная логика ещё не реализована полностью;
- данных для рекомендаций пока нет;
- преждевременно для этапа 7.

## Решение

Принимаем вариант A: на этапе 7 похожими товарами считаются товары из той же категории.

Для блока похожих товаров используется минимальное правило:

- показать до 3 активных неудалённых товаров;
- товары должны быть из той же активной категории;
- текущий товар должен быть исключён;
- товары с `stock_quantity = 0` можно показывать, но с состоянием `Нет в наличии`.

## Итоговое правило выборки

В похожие товары попадает товар, если:

1. товар активен;
2. товар не soft-deleted;
3. категория товара совпадает с категорией текущего товара;
4. категория активна;
5. товар не является текущим товаром;
6. результат ограничен максимум 3 товарами.

`stock_quantity = 0` не исключает товар из похожих товаров.

## Что не реализуем на этапе 7

На этапе 7 не реализуем:

- подбор по близкой цене;
- подбор по тегам;
- подбор по брендам;
- подбор по атрибутам;
- подбор по популярности;
- подбор по истории заказов;
- подбор по просмотрам;
- персональные рекомендации.

Эти варианты можно рассмотреть позже, когда появятся соответствующие данные и отдельное решение по рекомендательной логике.

## Последствия

Плюсы:

- решение реализуется на текущей модели без новых таблиц;
- не усложняет этап 7;
- не смешивает страницу товара с аналитикой и заказами;
- поведение понятно и предсказуемо;
- блок похожих товаров появляется уже на этапе 7.

Минусы:

- рекомендации будут грубыми;
- товары из одной категории не всегда действительно похожи;
- в будущем правило может потребовать пересмотра.

## Требования к реализации этапа 7

- Похожие товары выбираются только из той же категории.
- Текущий товар не должен попадать в блок похожих товаров.
- В блок попадают только активные неудалённые товары.
- Категория похожих товаров должна быть активной.
- Максимальное количество похожих товаров — 3.
- Товары без остатка можно показывать, но с состоянием `Нет в наличии`.
