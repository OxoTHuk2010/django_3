# ADR 0030: Политика seed demo-data

## Статус

Принято.

## Контекст

Проекту нужны предсказуемые демонстрационные данные для локальной проверки и презентации. Seed-команда не должна быть опасной для production и не должна хранить пароли в репозитории.

## Решение

- Demo-data создаётся management command `seed_demo_data`.
- Команда идемпотентна: повторный запуск обновляет seed-owned данные без дублирования.
- `--reset` требует `--yes` и разрешён только в local/demo окружении.
- Команда блокируется в production-like окружении.
- Demo-пароль не хранится в коде или документации.
- Если задан `MYSHOP_DEMO_PASSWORD`, он используется для demo-пользователей.
- Если `MYSHOP_DEMO_PASSWORD` не задан, demo-пользователи создаются с unusable password.

## Последствия

Плюсы:

- Локальная демонстрация воспроизводима.
- Reset seed-data безопасно ограничен.
- Репозиторий не содержит demo credentials.
- Demo-data поддерживает основные сценарии каталога, корзины, заказов, платежей и отзывов.

Минусы:

- Для входа под demo-пользователем нужно локально задать пароль.
- Seed-data требует сопровождения при изменении моделей.

## Инварианты

- Не использовать реальные персональные данные.
- Не удалять пользовательские данные вне seed-owned набора.
- Не выполнять destructive reset в production-like окружении.
- Пользовательские названия и тексты demo-data — на русском языке.
- Technical keys, `slug`, `SKU`, `username` и provider ids остаются ASCII.
