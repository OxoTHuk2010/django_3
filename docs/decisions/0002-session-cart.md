# ADR 0002: Подход к корзине

## Статус

В обсуждении.

## Контекст

Для web-интерфейса интернет-магазина нужна корзина. Изначальный план предполагал session-based корзину: данные корзины хранятся в Django session, а заказ создаётся из корзины на checkout.

В текущей модели также появился вариант database-backed корзины через `Cart` и `CartItem`. Поэтому решение нельзя считать принятым до выбора одного подхода.

## Варианты

### Вариант A: session-based cart

Корзина хранится в session.

Плюсы:

- простая реализация для web MVP;
- не требует авторизации;
- не требует таблиц корзины;
- соответствует исходному плану.

Минусы:

- корзина привязана к session;
- сложнее синхронизировать между устройствами;
- для API может потребоваться отдельная реализация.

### Вариант B: database-backed cart

Корзина хранится в БД.

Плюсы:

- данные корзины связаны с пользователем;
- проще делать API корзины для авторизованных пользователей;
- корзина не теряется при смене устройства.

Минусы:

- усложняет MVP;
- требует миграций и дополнительных constraints;
- нужно отдельно решить гостевую корзину.

## Решение

Не принято.

До завершения этапа моделей нужно выбрать один вариант и обновить этот ADR.
