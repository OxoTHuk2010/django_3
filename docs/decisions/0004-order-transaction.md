# ADR 0004: Создание заказа внутри транзакции

## Статус

Принято.

## Контекст

Checkout изменяет несколько связанных сущностей: заказ, позиции заказа, остатки товаров, платёж и корзину. Частичное выполнение операции может привести к неконсистентным данным.

Примеры рисков:

- заказ создан, но остатки не уменьшены;
- остатки уменьшены, но позиции заказа не созданы;
- два пользователя одновременно покупают последний товар;
- корзина очищена, но заказ не создан.

## Решение

Создание заказа должно выполняться в сервисном слое внутри `transaction.atomic()`.

Товары при проверке и изменении остатков должны блокироваться через `select_for_update()`.

Целевая функция:

```python
create_order_from_cart(user, cart, shipping_data)
```

## Последствия

Плюсы:

- заказ создаётся атомарно;
- снижается риск oversell;
- view остаётся тонкой;
- бизнес-логику проще тестировать.

Минусы:

- нужно аккуратно проектировать сервис;
- нужны тесты негативных и конкурентных сценариев;
- checkout нельзя реализовывать прямо во view.
