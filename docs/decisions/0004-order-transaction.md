# ADR 0004: Транзакционное создание заказа

## Статус
Запланировано

## Контекст

Создание заказа затрагивает несколько действий:

- создание Order
- создание OrderItem
- фиксация цены товара
- уменьшение stock
- создание Payment
- очистка корзины

Если часть действий выполнится, а часть нет, данные станут неконсистентными.

## Решение

Создавать заказ внутри `transaction.atomic()`.

Для блокировки товаров при оформлении использовать `select_for_update()`.

## Причины

- нельзя продать больше товара, чем есть на складе
- цена в OrderItem должна фиксироваться на момент заказа
- заказ и связанные сущности должны создаваться атомарно

## Последствия

+ Консистентность данных
+ Защита от race condition при покупке
+ Корректная история заказов

- Нужно аккуратно проектировать сервис создания заказа
- Возможны блокировки строк товаров при высокой конкуренции
