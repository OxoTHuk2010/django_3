# ADR 0006: Ограниченное использование soft delete в базовых моделях

## Статус

Принято.

## Контекст

В проекте возник конфликт C002: нужно ли добавлять механизм soft delete в общую базовую модель проекта.

Soft delete позволяет не удалять объект физически из базы данных, а помечать его как удалённый через поля `is_deleted` и `deleted_at`.

Добавлять soft delete в универсальную `TimeStampedModel` не нужно, потому что не все модели проекта должны поддерживать мягкое удаление. Для заказов, оплат, позиций заказа и других финансово или исторически значимых сущностей удаление должно управляться статусами, а не полем `is_deleted`.

На текущем этапе soft delete нужен только для сущностей каталога, которые можно скрыть из публичного отображения без физического удаления из базы данных.

## Решение

Принято не добавлять soft delete в `TimeStampedModel`.

`TimeStampedModel` содержит только общие временные поля:

```text
created_at
updated_at
```

Механизм soft delete реализуется отдельным абстрактным классом:

```text
SoftDeleteModel
```

На текущем этапе `SoftDeleteModel` разрешено использовать только для моделей каталога:

```text
catalog.Category
catalog.Product
```

Все остальные модели проекта не должны наследоваться от `SoftDeleteModel` без пересмотра этого ADR.

Если в будущем soft delete потребуется для других моделей, ADR 0006 должен быть возвращён на пересмотр.

## Последствия

Плюсы:

- `TimeStampedModel` остаётся простой и безопасной базовой моделью;
- soft delete не распространяется на все модели автоматически;
- область применения soft delete явно ограничена;
- снижается риск скрытия финансово или исторически значимых данных;
- `Product` и `Category` защищены от случайного физического удаления;
- решение можно расширить позже через пересмотр ADR.

Минусы:

- soft delete пока недоступен для других потенциальных моделей, например `Review`, `ProductImage`, `UserAddress`;
- при появлении новых требований потребуется пересмотр ADR;
- нужно явно контролировать, какие модели наследуются от `SoftDeleteModel`;
- для `Product` и `Category` нужно учитывать soft delete в публичных выборках.

## Правила реализации

- `TimeStampedModel` не содержит `is_deleted` и `deleted_at`.
- `SoftDeleteModel` используется только для `catalog.Category` и `catalog.Product`.
- Публичные selectors каталога должны исключать записи с `is_deleted=True`.
- Заказы, позиции заказа, платежи, отзывы и пользователи не используют soft delete на текущем этапе.
- Подключение `SoftDeleteModel` к другим моделям требует пересмотра ADR 0006.
