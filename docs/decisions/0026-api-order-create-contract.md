# ADR 0026: Создание заказа через API

## Статус

Принято.

## Контекст

API checkout должен использовать те же бизнес-правила, что и web checkout, и не принимать произвольный список позиций от клиента.

## Решение

- `POST /api/orders/` требует JWT.
- Заказ создаётся только из текущей DB-корзины пользователя.
- Клиент передаёт только контактные данные и адрес доставки.
- Список товаров, количество и цены берутся из корзины и доменных моделей.
- Создание заказа выполняется через `orders.services.create_order_from_cart()`.
- Payment outcome приходит из `apps.payment_emulator`.
- Корзина очищается только при `succeeded`.

## Последствия

Плюсы:

- Web и API checkout используют единые правила.
- Клиент не может подменить цены или позиции заказа.
- Non-success payment outcome сохраняет корзину для повторного действия.

Минусы:

- API не поддерживает one-shot checkout с переданными позициями.

## Инварианты

- Пустая корзина не оформляется.
- Остатки повторно проверяются внутри транзакции.
- `OrderItem.price` и `OrderItem.product_name` являются snapshot.
- Чужие заказы недоступны и скрываются через 404.
