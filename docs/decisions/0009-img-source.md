# ADR 0009: Источник изображения на детальной странице товара

## Статус

Принято.

## Контекст

На этапе 7 реализуется детальная страница товара.

В модели каталога уже есть `ProductImage`. Эта модель предназначена для хранения изображений товара и связана с `Product` через `related_name="images"`.

Ключевые поля `ProductImage`:

```text
product
image
alt_text
is_main
sort_order
created_at
updated_at
```

Также в проекте есть директория `src/prepare/`. В ней находятся подготовленные UI-ассеты и изображения, которые можно использовать позже как источник идей, демо-данных или seed-данных. Эта директория не должна становиться runtime-зависимостью текущей реализации магазина.

## Проблема

Для детальной страницы товара нужно определить источник изображения. Без явного решения есть риск:

- зашить в шаблон пути к demo-файлам;
- подбирать изображение по `slug` товара;
- смешать рабочую реализацию `MyShop` с подготовительными ассетами из `src/prepare/`;
- добавить временный placeholder, который потом придётся поддерживать как часть публичного UI.

## Рассмотренные варианты

### Вариант A: использовать только `ProductImage`

Плюсы:

- модель каталога остаётся единственным источником истины для изображений;
- реализация не зависит от demo-ассетов;
- товары не привязываются к конкретным `slug`;
- admin-загрузка изображений работает через доменную модель;
- поведение проще покрывать тестами.

Минусы:

- товар без загруженных изображений будет отображаться без картинки;
- для красивой демо-витрины позже потребуется отдельный seed/demo-этап.

### Вариант B: использовать `ProductImage` и fallback-placeholder

Плюсы:

- страница визуально выглядит заполненной даже без изображений;
- можно сохранить единый размер блока изображения.

Минусы:

- нужно добавить и поддерживать отдельный runtime-ассет;
- placeholder становится частью UI-решения, хотя этап 7 ещё не про полировку;
- появляется лишняя зависимость от статики до необходимости.

### Вариант C: подбирать изображения из `src/prepare/` по `slug`

Плюсы:

- быстро даёт визуально наполненную демо-страницу.

Минусы:

- рабочий код начинает зависеть от подготовительной директории;
- доменная логика связывается с demo-ассетами;
- товарные изображения начинают зависеть от конкретных `slug`;
- усложняется перенос проекта и будущий seed-этап.

## Решение

Принимаем вариант A: источником изображения на детальной странице товара является только `ProductImage`.

На этапе 7 не добавляем обязательный fallback-placeholder.

Если у товара нет связанных `ProductImage`, страница товара должна корректно отображаться без изображения. Допустимые варианты поведения:

- не показывать блок изображения;
- показать текстовое состояние `Изображение отсутствует`;
- оставить пустое место под изображение только если это не ломает вёрстку.

Основное изображение товара определяется через `ProductImage.is_main`.

Если у товара нет изображения с `is_main=True`, порядок выбора изображения может быть реализован так:

1. первое изображение по `sort_order`;
2. затем первое изображение по `id`.

Это правило не должно подменять главное решение: источник изображения всё равно только `ProductImage`.

## Недопустимое поведение

На этапе 7 нельзя:

- подбирать изображение по `slug` товара;
- использовать файлы из `src/prepare/` напрямую в рабочем шаблоне;
- жёстко связывать товарные изображения с demo-ассетами;
- зашивать пути к изображениям во view или template вне модели `ProductImage`;
- добавлять обязательный fallback-placeholder без отдельного решения.

## Последствия

Плюсы:

- `ProductImage` остаётся единственным источником истины для изображений товара;
- доменная логика не зависит от demo-ассетов;
- `src/prepare/` не смешивается с рабочей реализацией приложения;
- проект остаётся универсальным интернет-магазином `MyShop`;
- реализацию проще проверять тестами.

Минусы:

- товары без загруженных изображений могут выглядеть визуально пустыми;
- для красивой демо-витрины потребуется отдельный seed/demo-этап;
- шаблон детальной страницы должен явно обрабатывать отсутствие изображений.

## Требования к реализации этапа 7

- Получать изображения через связь `Product.images`.
- Не обращаться к `src/prepare/` из view, selector или template.
- Обработать состояние товара без изображений.
- Добавить тест на товар с изображением.
- Добавить тест на товар без изображения.
