# ADR 0032: Развитие Django Admin без замены базовой механики

## Статус

Принято.

## Контекст

Текущая админка построена на стандартном Django Admin: model admin настройки, filters, search fields, inline forms, permissions и admin actions.

Этап 23 требует сделать админку современнее и удобнее. Полная замена Django Admin внешним пакетом или отдельной панелью повышает риск сломать уже работающие CRUD-сценарии и права доступа.

## Решение

На первом проходе не заменять Django Admin внешним admin package.

`/admin/` остаётся основным staff entrypoint. Улучшения выполняются поверх стандартного Django Admin:

- branding `MyShop`;
- кастомные admin-шаблоны и стили;
- staff-only dashboard;
- улучшенная навигация и визуальное представление управления товарами;
- сохранение model admin CRUD, permissions, inline forms и admin actions.

Отдельная кастомная admin-панель допустима только после нового ADR, если стандартный Django Admin перестанет покрывать требования.

## Последствия

Плюсы:

- сохраняются стандартные права, формы, actions и ожидаемое поведение Django Admin;
- меньше миграционного риска перед этапами аналитики и production runtime;
- улучшения можно внедрять итеративно.

Минусы:

- дизайн ограничен возможностями кастомизации Django Admin;
- часть UX-требований может потребовать компромиссов;
- staff dashboard нужно явно отделять от публичного web UI.

## Инварианты

- `/admin/` остаётся рабочим staff entrypoint.
- Существующие model admin actions не удаляются без отдельного решения.
- Inline forms и permissions сохраняются.
- Внешний admin package не добавляется на первом проходе.

## Связанные конфликты

- `C034` — стандартная Django Admin vs современная удобная админка.
