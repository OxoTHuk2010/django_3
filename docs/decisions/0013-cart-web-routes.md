# ADR 0013: Web-маршруты и HTTP-контракт корзины

## Статус

Принято.

## Контекст

ADR 0002 фиксирует хранение корзины, но не определяет web-маршруты и HTTP-контракт действий корзины.

На этапе 8 нужно заменить disabled-кнопку добавления товара реальной POST-формой и определить:

- URL страницы корзины;
- URL добавления товара;
- URL изменения количества;
- URL удаления позиции;
- URL очистки корзины;
- допустимые HTTP-методы;
- идентификатор товара для cart-действий;
- поведение после успешного POST-запроса.

Конфликт C011 закрывается этим ADR.

## Решение

Для web-интерфейса корзины используются отдельные маршруты действий с передачей `product_id` в URL.

Итоговый HTTP-контракт:

| Действие | Метод | URL |
| --- | --- | --- |
| Просмотр корзины | `GET` | `/cart/` |
| Добавление товара | `POST` | `/cart/add/<int:product_id>/` |
| Изменение количества | `POST` | `/cart/update/<int:product_id>/` |
| Удаление позиции | `POST` | `/cart/remove/<int:product_id>/` |
| Очистка корзины | `POST` | `/cart/clear/` |

Изменение состояния корзины разрешено только через `POST`.

После успешного `POST` выполняется redirect. Базовое поведение этапа 8: redirect на `/cart/`.

`product_id` выбран как основной идентификатор cart-позиции, потому что корзина хранит товар по стабильному внутреннему идентификатору. Публичный `slug` остаётся частью URL каталога и страницы товара, но не используется как идентификатор позиции корзины.

## Отклонённые варианты

- Использовать `slug` в cart-URL: хуже согласуется с внутренним хранением корзины и создаёт зависимость cart-действий от публичного URL товара.
- Использовать один endpoint `/cart/` с `action=add|update|remove|clear`: усложняет view и ухудшает тестируемость отдельных действий.
- Разрешить изменения через `GET`: нарушает семантику HTTP и может привести к случайным изменениям корзины.

## Последствия

Плюсы:

- контракт прост для Django forms;
- каждое действие корзины имеет отдельный URL;
- web-корзина не смешивается с будущим REST API;
- тесты можно писать отдельно на добавление, изменение, удаление и очистку;
- cart-действия не зависят от изменения `slug` товара.

Минусы:

- URL менее человекочитаемые, чем варианты со `slug`;
- при ручном обращении к несуществующему `product_id` нужно корректно обработать отсутствие товара.

## Требования к реализации

- Добавить `apps/cart/urls.py` с перечисленными маршрутами.
- Подключить маршруты корзины в корневом `urls.py`.
- Все mutating views должны принимать только `POST`.
- Формы в шаблонах должны использовать CSRF.
- После успешного действия выполнять redirect.
- `GET`-запросы к mutating endpoints не должны менять корзину.
- Будущий REST API корзины должен иметь отдельный контракт и не обязан повторять web-маршруты.
