# ADR 0027: API-регистрация и JWT

## Статус

Принято.

## Контекст

API-клиенту после регистрации нужен авторизованный сценарий без отдельного ручного входа. Основной логин проекта остаётся `username`.

## Решение

- `POST /api/users/register/` создаёт пользователя.
- Регистрация требует `username`, `email`, `password`.
- После успешной регистрации API возвращает данные пользователя и JWT pair.
- `POST /api/users/login/` является compatibility alias для получения JWT pair.
- Основной token endpoint SimpleJWT сохраняется: `POST /api/token/`.

## Последствия

Плюсы:

- API-клиент может продолжить работу сразу после регистрации.
- Login alias удобен для клиентов и не ломает стандартные JWT endpoints.
- Основной login identifier остаётся согласованным с web/admin: `username`.

Минусы:

- Нужно явно документировать, что `email` не является основным логином.

## Инварианты

- Пароли не возвращаются в API response.
- Ошибки регистрации используют единый API error contract.
- Секреты и реальные пароли не фиксируются в документации или тестовых fixtures.
