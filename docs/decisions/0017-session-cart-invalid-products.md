# ADR 0017: Недоступные товары и битые product_id в session-cart

## Статус

Принято.

## Контекст

Session-cart хранит минимальные данные:

- `product_id`;
- `quantity`.

Цена, активность, остаток и остальные товарные данные должны каждый раз браться из актуальной модели `Product`.

За время жизни session товар может быть удалён, отключён, soft-deleted, перемещён в скрытую категорию, распродан или изменён по цене. Нужно определить, как корзина должна вести себя при таких изменениях.

Конфликт C015 закрывается этим ADR.

## Решение

Нормализация корзины выполняется в сервисном слое корзины при построении snapshot, например внутри `get_cart_snapshot(request)` или внутренней helper-функции.

Из корзины автоматически удаляются позиции, если товар:

- не найден по `product_id`;
- soft-deleted;
- имеет `is_active=False`;
- находится в неактивной или скрытой категории.

Товары с `stock_quantity = 0` не удаляются автоматически. Они остаются видимыми пользователю, но помечаются как недоступные для оформления.

Если `quantity` в корзине больше текущего остатка, количество не обрезается silently при просмотре корзины. Позиция остаётся в корзине с предупреждением, а checkout должен быть недоступен до явного изменения количества пользователем.

Сервис корзины должен возвращать warnings для шаблона.

## Причины

- Удалённый или скрытый товар нельзя корректно использовать в checkout.
- Товар без остатка всё ещё можно показать пользователю с понятной причиной недоступности.
- Скрытое обрезание количества ухудшает прозрачность поведения корзины.
- View не должна самостоятельно нормализовать корзину.

## Отклонённые варианты

- Показывать все битые позиции: невозможно корректно отобразить товар, которого больше нет в БД.
- Удалять товары с нулевым остатком: пользователь не поймёт, почему позиция исчезла.
- Падать с ошибкой при невалидной позиции: корзина может стать неоткрываемой.
- Silently-обрезать количество до остатка при просмотре: пользователь не увидит изменение.

## Последствия

Плюсы:

- корзина не ломается из-за битых `product_id`;
- checkout не получает удалённые, скрытые или отключённые товары;
- пользователь видит объяснимое состояние для распроданных товаров;
- логика нормализации находится в одном месте.

Минусы:

- snapshot корзины становится сложнее;
- нужно поддерживать warnings для шаблона;
- checkout обязан проверять `can_checkout`;
- требуется больше тестов на edge cases.

## Требования к реализации

- Session-cart не должен хранить цену товара.
- Product всегда перечитывается из БД при построении snapshot.
- Удаление битых и скрытых позиций должно сохраняться обратно в session.
- Snapshot должен различать `is_empty`, `has_unavailable_items`, `can_checkout` и warnings.
- Checkout должен быть заблокирован, если в корзине есть недоступные или некорректные позиции.
