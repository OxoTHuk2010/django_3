# ADR 0005: Базовая доменная модель интернет-магазина

## Статус

Принято.

## Контекст

Проект реализует интернет-магазин на Django и DRF. Нужно разделить ответственность между приложениями и не складывать всю бизнес-логику в одно приложение.

## Решение

Использовать отдельные приложения по доменным областям:

- `users` — пользователи и профиль;
- `catalog` — категории, товары, изображения товаров;
- `cart` — корзина;
- `orders` — заказы и позиции заказов;
- `reviews` — отзывы;
- `payments` — оплата;
- `common` — общие абстрактные модели;
- `api` — сборка API-маршрутов и схемы.

## Причины

- каждая область ответственности изолирована;
- проще писать тесты и документацию;
- проще развивать API рядом с доменным кодом;
- проект ближе к реальной backend-структуре.

## Последствия

Плюсы:

- чистые границы модулей;
- проще сопровождать проект;
- проще переходить к admin, web и API этапам.

Минусы:

- больше файлов и связей между приложениями;
- нужно следить за циклическими импортами;
- документацию нужно обновлять при изменении модели.
