# ADR 0016: Политика количества товара в корзине

## Статус

Принято.

## Контекст

Для корзины нужно одинаково трактовать количество товара во всех сценариях:

- добавление товара;
- изменение количества на странице корзины;
- удаление позиции;
- объединение session-cart и DB-cart после авторизации.

ADR 0002 фиксирует общий принцип: нельзя оформлять количество больше доступного остатка, а при merge нужно учитывать остаток и системный лимит. Но до этого ADR не было точного правила для операций `add`, `update` и `merge`.

Конфликт C014 закрывается этим ADR.

## Решение

Вводится единая политика количества:

- `add_to_cart` увеличивает количество уже существующей позиции;
- `update_cart_item` заменяет количество позиции новым значением;
- `remove_from_cart` удаляет позицию целиком;
- `clear_cart` очищает всю корзину;
- системный максимум одной позиции: `MAX_CART_ITEM_QUANTITY = 99`.

Для пользовательских операций `add` и `update` превышение лимитов считается ошибкой. Сервис возвращает ошибку и не меняет корзину, если итоговое количество:

- меньше `1`;
- больше `product.stock_quantity`;
- больше `MAX_CART_ITEM_QUANTITY`;
- относится к неактивному, soft-deleted или недоступному товару.

Для merge после авторизации используется безопасное ограничение:

`min(db_quantity + session_quantity, product.stock_quantity, MAX_CART_ITEM_QUANTITY)`

Это исключение допустимо только для merge, потому что merge выполняется как техническая операция согласования двух корзин, а не как явное пользовательское изменение количества.

## Отклонённые варианты

- Сделать `add` заменой количества: повторное нажатие "Добавить в корзину" будет неочевидным для пользователя.
- Автоматически обрезать пользовательское количество до остатка: пользователь не увидит бизнес-ошибку.
- Не вводить системный максимум позиции: можно получить неадекватные значения в session или DB.

## Последствия

Плюсы:

- поведение `add` и `update` становится предсказуемым;
- пользователь явно узнаёт о превышении остатка;
- merge остаётся безопасным и не создаёт невозможные количества;
- checkout получает корзину с понятными ограничениями.

Минусы:

- сервисы должны возвращать структурированную ошибку для отображения пользователю;
- нужно отдельно тестировать `add`, `update` и `merge`;
- в snapshot корзины нужно показывать предупреждения, если остаток изменился после добавления товара.

## Требования к реализации

- Добавить `MAX_CART_ITEM_QUANTITY = 99` в слой корзины.
- Проверять количество в сервисах, а не во views.
- Не менять корзину при ошибке пользовательской операции.
- Покрыть тестами увеличение количества, замену количества, превышение остатка, превышение системного лимита и merge.
