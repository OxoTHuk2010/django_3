# ADR 0011: Отзывы и рейтинг на странице товара до реализации review service

## Статус

Принято.

## Контекст

На этапе 7 реализуется детальная страница товара.

Roadmap этапа 7 предполагает отображение рейтинга и отзывов на странице товара. При этом полноценный сервис отзывов относится к более позднему этапу.

В проекте уже есть модель `Review`. Она содержит:

- связь с пользователем;
- связь с товаром;
- рейтинг;
- текст отзыва;
- статус модерации;
- признак подтверждённой покупки.

Бизнес-правила создания отзывов ещё не реализованы. Позже отдельно должны быть определены и реализованы:

- кто может оставить отзыв;
- можно ли оставить отзыв только после покупки;
- сколько отзывов пользователь может оставить на один товар;
- как работает service-layer отзывов;
- кто может публиковать, скрывать или отклонять отзывы.

Конфликт `C009` связан с тем, можно ли показывать отзывы и рейтинг до реализации полноценного review service.

## Рассмотренные варианты

### Вариант A: показывать только опубликованные отзывы без формы создания

Плюсы:

- не нарушаются будущие правила создания отзывов;
- можно безопасно использовать существующую модель `Review`;
- страница товара получает полезный read-only блок;
- поведение легко покрыть тестами.

Минусы:

- нужно строго фильтровать только публичные отзывы.

### Вариант B: не показывать отзывы до будущего этапа review service

Плюсы:

- этап 7 становится проще;
- нет риска преждевременной логики отзывов.

Минусы:

- roadmap этапа 7 закрывается не полностью;
- страница товара выглядит менее полной.

### Вариант C: добавить форму отзыва уже на этапе 7

Плюсы:

- функциональность выглядит богаче.

Минусы:

- преждевременно смешивает этап 7 с будущим review service;
- требует проверки покупки;
- требует service-layer;
- повышает риск нарушения бизнес-правил.

## Решение

Принимаем вариант A: на этапе 7 показываем только read-only опубликованные отзывы и средний рейтинг по опубликованным отзывам.

Форма создания отзыва на этапе 7 не реализуется.

Источником данных является существующая модель `Review`.

Публичными считаются только отзывы со статусом:

```text
Review.Status.PUBLISHED
```

Недопустимо показывать отзывы в статусах:

- `Review.Status.DRAFT`;
- `Review.Status.PENDING`;
- `Review.Status.REJECTED`;
- `Review.Status.HIDDEN`;
- любые будущие непубличные статусы.

## Допустимое поведение на этапе 7

На детальной странице товара можно отображать:

- список опубликованных отзывов;
- средний рейтинг товара;
- количество опубликованных отзывов;
- состояние `Отзывов пока нет`, если опубликованных отзывов нет.

## Недопустимое поведение

На этапе 7 нельзя:

- добавлять форму создания отзыва;
- проверять право оставить отзыв;
- создавать или изменять отзывы из страницы товара;
- показывать непубличные отзывы;
- считать рейтинг по непубличным отзывам.

## Итоговое правило

Этап 7 использует отзывы только в режиме чтения.

Создание отзывов, проверка покупки и полноценный review service реализуются позже.

## Последствия

Плюсы:

- roadmap этапа 7 закрывается без преждевременной реализации review service;
- страница товара получает read-only блок отзывов;
- не нарушаются будущие правила создания отзывов;
- модель `Review` используется безопасно;
- поведение просто покрывать тестами.

Минусы:

- пользователь не сможет оставить отзыв на этапе 7;
- нужна строгая фильтрация queryset;
- полноценная логика отзывов всё равно остаётся будущим этапом.

## Требования к реализации этапа 7

- Получать отзывы через связь `Product.reviews`.
- Фильтровать отзывы по `status=Review.Status.PUBLISHED`.
- Считать средний рейтинг только по опубликованным отзывам.
- Считать количество отзывов только по опубликованным отзывам.
- Не добавлять форму создания отзыва.
- Корректно отображать состояние без опубликованных отзывов.
