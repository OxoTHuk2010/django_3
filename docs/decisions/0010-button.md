# ADR 0010: Кнопка покупки на странице товара до реализации корзины

## Статус

Принято.

## Контекст

На этапе 7 реализуется детальная страница товара.

По roadmap на странице товара должна быть видна будущая точка добавления товара в корзину. При этом полноценная корзина реализуется позже, на этапе 8.

Если на этапе 7 добавить активную кнопку покупки или POST-форму без backend-логики корзины, пользователь увидит ложное поведение: интерфейс будет выглядеть рабочим, но товар фактически не будет добавляться в корзину.

Конфликт `C008` связан с тем, как должна выглядеть кнопка покупки до реализации корзины.

## Рассмотренные варианты

### Вариант A: не показывать кнопку покупки до этапа 8

Плюсы:

- нет ложного действия;
- этап 7 остаётся read-only.

Минусы:

- страница товара выглядит менее похожей на интернет-магазин.

### Вариант B: показать disabled-кнопку с пояснением

Плюсы:

- пользователь видит будущую точку действия;
- нет ложной отправки формы;
- решение не нарушает порядок этапов;
- будущую активную форму проще добавить на этапе 8.

Минусы:

- нужно явно протестировать disabled-состояние;
- нужно добавить понятное пояснение в шаблон.

### Вариант C: сделать временную frontend-симуляцию корзины

Плюсы:

- страница выглядит интерактивной.

Минусы:

- противоречит ADR 0002 по архитектуре корзины;
- создаёт временное состояние, которое не связано с backend;
- может запутать пользователя и усложнить замену на настоящую корзину.

## Решение

Принимаем вариант B: на этапе 7 показываем disabled-кнопку покупки с пояснением, что корзина будет добавлена позже.

На детальной странице товара должна отображаться будущая точка действия, но без возможности отправить форму.

До реализации этапа 8 запрещено добавлять активную POST-форму добавления товара в корзину.

## Допустимое поведение на этапе 7

- Для товара с `stock_quantity > 0` показывать disabled-кнопку `Добавить в корзину`.
- Рядом или под кнопкой показывать пояснение, что корзина будет доступна на следующем этапе.
- Для товара с `stock_quantity = 0` показывать отдельное состояние `Нет в наличии`.
- Не выполнять POST-запросы на добавление товара в корзину.
- Не создавать временную frontend-корзину.

## Недопустимое поведение

На этапе 7 нельзя:

- добавлять активную кнопку покупки без backend-логики;
- добавлять форму, которая отправляет POST-запрос в несуществующий cart/checkout endpoint;
- хранить временную корзину в `localStorage`, `sessionStorage` или cookie;
- имитировать успешное добавление товара в корзину;
- подключать временную логику, которую придётся удалять на этапе 8.

## Итоговое правило

Этап 7 показывает намерение купить товар, но не реализует покупку.

Реальная логика добавления товара в корзину появляется только на этапе 8.

## Последствия

Плюсы:

- пользователь видит будущую точку действия;
- нет ложной отправки формы;
- не нарушается порядок roadmap;
- решение не конфликтует с ADR 0002;
- этап 8 сможет заменить disabled-кнопку на рабочую форму.

Минусы:

- покупка товара на этапе 7 фактически недоступна;
- нужно добавить тесты на disabled-состояние;
- нужно явно объяснить пользователю, почему кнопка неактивна.

## Требования к реализации этапа 7

- Кнопка покупки не должна выполнять POST-запрос.
- Для доступного товара показывается disabled-кнопка `Добавить в корзину`.
- Для товара без остатка показывается состояние `Нет в наличии`.
- Активная форма добавления в корзину реализуется только на этапе 8.
- Страница товара не должна зависеть от приложения корзины до этапа 8.
