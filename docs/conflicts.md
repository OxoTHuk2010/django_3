# Конфликты и решения

Файл фиксирует архитектурные вопросы, которые блокируют реализацию или требуют ADR.

## Текущий статус

Открытых блокирующих конфликтов нет.

Этап 28 исключён из текущего scope. Этапы 29-30 реализованы: CI и production runtime.

## Правила ведения

- Новый конфликт получает код `CXXX`, краткое описание, статус и ссылку на ADR, если ADR нужен.
- Если вопрос относится к обычному бизнес-правилу, маршруту или UI-состоянию, он фиксируется в профильной документации без ADR.
- ADR требуется для решений, которые меняют границы приложений, публичный API, security model, production runtime, транзакционную модель или правила хранения данных.

## Когда добавлять новый конфликт

Новый конфликт нужен, если невозможно безопасно продолжить реализацию без выбора одного из вариантов. Примеры: смена способа аутентификации, изменение публичных URL/API, добавление реального платёжного провайдера, изменение production deployment model, изменение правил хранения персональных данных.
